# РГР: Клиент-серверное приложение удалённого выполнения команд

Безопасный сервер на **C** принимает команды от клиента, выполняет их в ОС Linux
и возвращает вывод. Доступ — только после авторизации. Клиент — с графическим
интерфейсом (Python + Tkinter).

## Состав

```
rgr/
├── Makefile               сборка и запуск
├── README.md              этот файл
├── src/
│   ├── server.c           сервер на C (сокеты, потоки, авторизация)
│   ├── rcs_client.py      сетевой модуль клиента (протокол RCS)
│   ├── client_gui.py      графический клиент (Tkinter)
│   └── mkuser.py          добавление пользователей в users.conf
└── tests/
    └── test_protocol.py   автотесты протокола
```

## Сборка и запуск

```bash
# 1. Собрать сервер
make

# 2. Запустить сервер (порт по умолчанию 5555)
make run            # или: cd src && ./server 5555

# 3. В другом терминале — графический клиент
make client         # или: cd src && python3 client_gui.py

# Автотесты
make test
```

При первом запуске сервер создаёт файл `users.conf` с учётной записью по
умолчанию **admin / admin123**. Пароль следует сменить:

```bash
cd src
python3 mkuser.py myuser MyStrongPass   # добавить пользователя
# затем удалить строку admin из users.conf при необходимости
```

Для графического клиента в Linux нужен пакет `python3-tk`:
```bash
sudo apt install python3-tk
```

## Протокол RCS

Кадр: `[4 байта длины, big-endian][полезная нагрузка UTF-8]`.
Полезная нагрузка имеет вид `ТИП\nтекст`.

| Шаг | Направление       | Сообщение                        |
|-----|-------------------|----------------------------------|
| 1   | клиент → сервер   | `USER\n<логин>`                  |
| 2   | сервер → клиент   | `CHALLENGE\n<соль>\n<nonce>`     |
| 3   | клиент → сервер   | `RESP\n<ответ>`                  |
| 4   | сервер → клиент   | `OK\n…` или `ERR\n…`             |
| 5   | клиент → сервер   | `CMD\n<команда>`                 |
| 6   | сервер → клиент   | `OUT\n<вывод+код возврата>`      |
| 7   | клиент → сервер   | `QUIT`                           |

Ответ авторизации:
`H = SHA256(соль + пароль)`, далее `ответ = SHA256(H + nonce)`.
Пароль по сети **не передаётся**.

## Реализованные меры безопасности

1. **Challenge-response** — пароль не уходит в сеть; одноразовый `nonce`
   защищает от повтора (replay).
2. **Хранение паролей** — только солёный хэш SHA-256, не открытый текст.
3. **Авторизация обязательна** — команды выполняются лишь после успешного входа.
4. **Защита от перебора** — пауза и разрыв соединения при неверном пароле.
5. **Защита от перечисления пользователей** — для несуществующего логина
   сервер всё равно отдаёт правдоподобную соль/nonce.
6. **Кадрирование с ограничением длины** — защита от переполнения и DoS.
7. **Ограничение объёма вывода** (1 МБ).
8. **Аудит-журнал** (`server.log`): время, IP, пользователь, команда.

## Ограничения (для боевой эксплуатации)

- Канал не шифруется: для защиты от MITM добавьте TLS (OpenSSL/`libssl`).
- Команды выполняются с правами процесса сервера — **не запускайте от root**;
  при необходимости ограничьте набор команд белым списком.
